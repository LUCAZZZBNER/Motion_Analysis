# 架构想法

更新：2026-10-02｜状态：已选择小测试方式，正式产品架构以后讨论。

## 目前的概念

- **动作**：用户做什么，例如深蹲或投篮。
- **分析能力**：程序能从视频中提取、计算什么。
- **参考模板**：用户选择与哪个动作或一组动作比较。

把三者分开，便于以后增加动作和参考对象。这是原讨论的产品思路，不要求现在建立复杂服务或插件体系。

## 简单流程草图

视频 → 提取人体动作 → 展示动作 → 与参考比较。

先用一个动作验证这个流程，再决定需要保存哪些结果、如何复用。

本次小测试已接入 MediaPipe Pose Landmarker Lite：选择两段视频 → 浏览器逐帧提取姿态 → 绘制骨架、对比图表和轨迹。Python 只提供本机页面，没有完整前后端框架或云端调用。模型资源使用已授权的 assets 目录；硬盘上限 5 GB，运行内存上限 1 GB，真人视频峰值仍需验证。[运行说明](../local_pose_test/README.md)

## 以后需要讨论

- 正式产品的分析放在用户设备还是服务器？
- 第一次是否需要保存数据和多人使用？

技术栈、数据库、云平台、队列、服务拆分和部署方案暂不确定，等实际需求出现再选择。
